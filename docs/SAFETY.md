## 2. 控制权与状态机规则

### 2.1 控制权优先级

所有下行控制指令由单一节拍器统一仲裁（默认 200 ms 周期）。单船指令的仲裁优先级如下：

| 优先级 | 判定条件 | 结果 |
|---:|---|---|
| **1** | 自动控制激活（定艏 / 定速 / 任务 / 返航） | 强制下发自动控制指令，**无视手动输入** |
| **2** | 驾驶台安全锁未勾选 | **静默不发送任何字节** |
| **3** | 实体手柄偏离中位（> 1%） | 下发手柄指令 |
| **4** | 实体手柄回中瞬间 | 强制下发一次 `(0,0)` 刹车 |
| **5** | 实体手柄静默 | 退回虚拟摇杆缓存值（若存在操作） |

> **安全锁（`lock_checkbox`）是唯一的手动总闸**。未勾选时，第 3-5 级全部失效，手柄推到底也不会发出任何字节。

### 2.2 手动接管自动模式

代码中不存在独立的遥控器（RC）硬件接收链路。所谓的“手柄强行接管”发生在软件层：

当实体手柄偏离中位超过 **15%**（`abs(x) > 15` 或 `abs(y) > 15`）时，系统将立即清除定艏、定速、任务、位姿返航等自动模式标志，并触发 `sig_manual_override` 信号，随后本帧走手动通道。

> **实船注意**：如果地面站进程崩溃、笔记本断电或无线链路中断，手柄无法接管——因为手柄数据同样需要经过地面站打包才能下发。

### 2.3 状态流转与动力上锁

| `mode` | 含义 | 地面站是否下发 |
|---:|---|---|
| `0x00` | 🔒 锁定 | ✅ 初始化帧、急停帧使用 |
| `0x01` | 🕹️ 手动 | ✅ 所有正常运行时的控制帧 |
| `0x02` | 🎯 返航 | ❌ 仅用于遥测解析后的 UI 显示 |

**典型流转**：
1. 连接串口 / UDP。
2. 点击「初始化」→ 发送 `mode=0x00` 帧（PWM 全 1500，继电器吸合，传感器开启）。此时执行器中位待命。
3. 勾选「🔒 解锁手动控制」→ 可下发 `mode=0x01` 手动帧。
4. 触发急停 → 发送 `mode=0x00` 帧（PWM 全 1500，继电器断开，传感器关闭），系统进入锁定态。

> **动力上锁机制**：初始化帧的 `mode` 是 `0x00`，但继电器全部吸合（执行器通电待命）。真正切断动力的操作是**急停**（继电器断开）。

## 3. 急停与失联保护机制

### 3.1 软件急停（E-Stop）

**触发入口**：
- 工具栏「🚨 全局紧急停机」：同时急停船坞与子船。
- 侧栏「🛑 动力急停」按钮：单船急停。
- 手柄按键 2：触发全局急停。

**急停指令内容**：
构造一帧标准的 33 字节下行控制帧，`mode=0x00`，四路 PWM 全部为 `1500`（零推力），继电器状态为 `[0, 0, 0, 0, 1, 0]`（断开动力），IMU/GPS 关闭。

**急停的“粘性”保护**：
急停后，系统会同步更新内部镜像状态，防止后续正常的控制帧用旧值覆盖急停。即便再次推手柄，继电器也会保持断开状态。**必须显式重新点击「初始化」才能恢复动力**。

> **急停是软件指令，不是机械制动**。急停后船会因惯性继续滑行。

**急停的局限**：
- 急停帧只发送一次，无重发机制，无 ACK 确认。
- 若通信线程未运行，急停操作仅在日志中记录错误，不会重试或弹窗告警。
- 急停发送未强制 flush，串口缓冲区中积压的旧控制帧可能排在急停帧之前发出。
- 若地面站进程崩溃或断电，急停按钮不可用。

### 3.2 通信失联保护

> ⚠️ **地面站不具备“丢包后自动停船”的逻辑**。

地面站实现的失联检测仅用于 UI 状态显示：
- **远端遥测超时**：连续 3.0 秒收不到有效遥测帧，UI 显示“远端失联”。
- **延迟探测超时**：2.0 秒无延迟包回应，延迟面板显示 `--`。

> 🔴 **实船部署必须遵守**：地面站采用 fire-and-forget 模式，无心跳机制。**MCU 固件必须自行实现“控制指令超时停船”保护**。若固件未实现此保护，地面站断线后船将按最后一帧的推力持续航行。

### 3.3 指令超时与松手刹车

地面站不实现超时兜底，其发送语义如下：
- **手柄持续操作**：按采样间隔持续下发指令。
- **手柄回中**：下发一次 `(0,0)` 指令，PWM 全 1500。
- **手柄一直静止 / 安全锁未勾选**：完全静默，不发送任何字节。

地面站提供了独立的刹车函数 `send_stop_cmd()`。船坞侧该函数默认开启 flush（清空串口缓冲），子船侧未开启。子船刹车可能被串口缓冲区积压的旧帧延迟。

### 3.4 速度与推力限幅

系统内置以下限幅保护，防止指令跳变：
- 物理极速钳位：2.0 m/s。
- 加速度限幅：0.5 m/s²。
- PID 输出粗限幅：±1.0。
- 手柄死区：10%。
- 推进器 PWM 硬限幅：主推（船坞 1000-2000 / 子船 1300-1800），转向（船坞 1300-1700 / 子船 1400-1600）。

## 4. 通信与数据校验

### 4.1 帧结构与校验算法

校验算法为单字节累加和（`sum(data) & 0xFF`）。

| 方向 | 帧长 | 帧头 | 帧尾 | 校验和位置 |
|---|---:|---|---|---|
| 下行 | 33 字节 | `0xAA` | `0x55` | Byte31 |
| 上行 | 59 字节 | `0xBB` | `0xCC` | 倒数第 2 字节 |
| 上行（双温度） | 65 字节 | `0xBD` | `0xCC` | 倒数第 2 字节 |
| 扩展指令 | 5/6/9/13 字节 | `0xFD` | `0x55` | 倒数第 2 字节 |

> 累加和只能检出单字节错误与部分多字节错误，无法检出字节换位。若链路误码率高，建议在 MCU 侧升级为 CRC-16。

### 4.2 上行帧校验与坏帧处理

上行帧校验检查三道关卡：帧头已知、帧尾正确、累加和匹配。
遇到坏帧时，系统丢弃该帧的 1 个字节并重新搜索下一帧头，确保后续好帧不被吞掉。坏帧为静默丢弃，无日志计数，可通过 LSLT 延迟面板的丢包率间接观察链路质量。

### 4.3 下行帧无校验、无重传

地面站只打包、不校验，也不等待 MCU 的 ACK。下行帧无序列号字段，无重发机制，同一帧重复到达会被 MCU 执行两次。

### 4.4 隐式信封（LSLT）兼容风险

在 UDP 链路下，一旦地面站收到对端的延迟探测回应（PONG），后续所有指令都会被自动包裹进 21 字节的 LSLT COMMAND 头中。

> **排查线索**：若指令发出去但船不动，请先检查对端是否支持解析此信封。旧固件可能无法拆包而直接丢弃。

## 5. 开发者与实船部署安全须知

### 5.1 强制测试流程

**强烈建议按以下顺序逐级验证，任何一级未通过不得进入下一级**：

| 级别 | 环境 | 验证内容 |
|---:|---|---|
| **L0** | 纯软件 / 单元测试 | 协议打包解析、校验和、限幅计算 |
| **L1** | Unity 数字孪生 | 控制算法、PID 参数、任务导航、状态机 |
| **L2** | 实船架空 / 拆桨 | 电机转向、推力分配、继电器时序 |
| **L3** | 实船下水 | 低速、近距离、有人看管 |

> **孪生调通 ≠ 实船调通**。孪生内的力映射曲线是可调的，修改后将不再代表真船。L2（拆桨测试）绝对不可跳过。

### 5.2 硬件急停要求（强制）

> 🔴 **必须在实船上保留一套完全独立于软件的物理断电开关**。

基于软件急停的局限性（发一次不重发、无 ACK、依赖软件存活），在以下场景中软件急停会失效：地面站进程崩溃、笔记本断电、无线链路中断、串口线脱落、树莓派死机、MCU 固件跑飞、急停帧在链路丢失。

**推荐的硬件急停设计**：
- 物理开关直接切断推进器电源（串联在电池与电调之间）。
- 位置在操作员伸手可及处，不依赖任何无线链路。
- 具备自锁功能（按下后保持断开）。
- 船坞与子船各配一个。
- 每次下水前测试。

### 5.3 操作员下水前检查清单

- [ ] 已阅读并理解本安全文档与程序内免责声明。
- [ ] 硬件物理断电开关已安装、已测试、可触及。
- [ ] 已拆桨完成电机转向与推力分配验证。
- [ ] MCU 固件的“控制指令超时保护”已确认实现并实测。
- [ ] 地面站急停按钮已实测，船确实停转。
- [ ] 通信链路质量已确认。
- [ ] 作业水域已勘察，安全半径内无人员、无其他船只。
- [ ] 至少两人在场（操作员 + 观察员）。
- [ ] 救生设备、打捞工具就位。
- [ ] 天气与水文条件在安全范围内。

### 5.4 实船部署的增强待办

接入真实硬件前，请确认以下增强项已由工程团队落实：
1. 在 MCU 固件实现控制指令超时停船保护。
2. 在 MCU 固件实现急停指令的连续重发与遥测确认。
3. 为子船 `send_stop_cmd()` 增加 flush 参数。
4. 如需高可靠性，增加独立遥控器（RC）硬件链路及硬件仲裁。
5. 升级通信校验为 CRC-16。
6. 统一返航指令为标准 33 字节帧，或明确文档化现有魔数帧的校验例外。
